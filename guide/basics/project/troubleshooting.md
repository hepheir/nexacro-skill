# 문제가 생기면 어디부터 확인하나요?

[매뉴얼 목차](../../README.md)

**문제가 생긴 구간을 먼저 좁힙니다.** 소스·생성 파일·화면 데이터·서버 응답을 한꺼번에 바꾸기보다 증상에 맞는 지점부터 봅니다.

## 증상별 첫 확인 지점

| 증상 | 먼저 볼 것 |
| --- | --- |
| 받은 프로젝트가 실행되지 않음 | 라이브러리 버전·Generate 결과 |
| 저장해도 화면이 그대로임 | 자동 생성 옵션·생성 경로·실행 URL |
| 버튼이 반응하지 않음 | 이벤트 속성의 함수 연결 |
| 한 번 눌렀는데 두 번 실행됨 | 디자인·동적 이벤트 등록 중복 |
| 스타일이 적용되지 않음 | 클래스 정의·개별 속성·상태 |
| 데이터는 있는데 상세가 비어 있음 | 현재 행·컬럼·value 바인딩 |
| Combo의 현재 값이 안 나옴 | 선택값 바인딩·목록 코드 일치 |
| 조회 직후 이전 값이 읽힘 | 결과를 callback에서 읽는지 |
| 화면에서 삭제했는데 DB에는 남음 | 저장 요청·삭제 데이터·서버 처리 |

## 어디에서 로그를 보나요?

Generate 오류와 NRE 실행 로그는 Studio Output을 먼저 봅니다. 브라우저 Script 오류는 개발자 도구 Console, 요청 URL·상태·응답은 Network에서 확인합니다. 서버 업무·SQL 오류는 WAS 로그와 서버 디버거에서 찾습니다.

여러 오류가 연달아 나오면 최초 오류부터 확인합니다. 생성된 JS에서 오류 위치를 찾았더라도 수정은 연결된 원본 XFDL/XJS에 합니다.

## QuickView에서만 실패한다면

로그인·전역 Dataset·공통 초기화가 필요한 화면인지 확인합니다. 전체 Application 실행과 환경이 같다고 가정하지 않습니다. 재현 조건과 첫 오류 메시지를 함께 기록하면 원인을 좁히기 쉽습니다.
