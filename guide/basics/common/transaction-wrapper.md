# 공통 통신 함수는 무엇을 대신 처리하나요?

[매뉴얼 목차](../../README.md)

**여러 화면에서 반복되는 URL 구성·로딩·오류·세션 처리를 모아 둔 함수입니다.** 넥사크로의 기본 `transaction()`을 감싸는 형태로 구성할 수 있습니다.

```text
화면 조회 함수
  → 공통 통신 함수
    → transaction()
      → 공통 callback
        → 화면 callback
```

위 흐름은 예시이며 실제 회사 코드의 호출 순서를 확인합니다.

## 공통과 화면의 역할

| 위치 | 처리하는 내용의 예 |
| --- | --- |
| 공통 통신 함수 | URL·공통 인자·기본 옵션 구성, 로딩 시작 |
| 공통 callback | 오류·세션 처리, 로딩 종료 |
| 화면 callback | 조회 후 행 선택, 업무별 후처리 |

`gfnTransaction`이라는 이름을 발견해도 기본 API라고 생각하면 안 됩니다. 회사에서 만든 함수이므로 인자 순서와 동작을 확인해야 합니다.

## 호출 전에 확인할 세 가지

첫째, Dataset 매핑과 서비스 ID를 함수가 바꾸거나 자동 구성하는지 확인합니다. 둘째, 실패했을 때도 화면 callback을 호출하는지 확인합니다. 셋째, 메시지와 로딩 종료를 어느 쪽에서 담당하는지 확인합니다.

공통 코드가 이미 오류 메시지를 띄우는데 화면에서도 같은 메시지를 띄우면 중복 안내가 생깁니다. 반대로 성공만 가정하면 실패 시 후처리가 빠질 수 있습니다.

새 화면에서는 동작하는 기존 화면의 호출 예제와 공통 함수 정의를 함께 읽습니다. 다른 프로젝트의 비슷한 이름의 함수와 인자가 같다고 가정하지 않습니다.
