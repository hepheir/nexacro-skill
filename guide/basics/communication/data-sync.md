# 화면에서 바꾼 값은 언제 DB에 저장되나요?

[매뉴얼 목차](../../README.md)

**서버에 저장을 요청하고 서버가 DB 처리를 완료했을 때 반영됩니다.** Dataset 변경, 서버 저장, 화면 결과 갱신은 각각 구분해야 합니다.

```text
조회: DB → 서버 응답 → Dataset → 화면
수정: 사용자 입력 → Dataset 변경 (DB는 아직 그대로)
저장: 변경 데이터 → 서버 검증·SQL 처리 → 결과 응답 → 화면 반영 또는 재조회
```

## 서버에는 어떤 데이터를 보내나요?

변경 행을 받는 API라면 `in_emp=ds_emp:U`처럼 전송할 수 있습니다. 전체 데이터가 필요한 API는 그 계약에 맞는 옵션을 사용합니다.

| 화면의 변경 | 서버 처리의 예 |
| --- | --- |
| 새 행 추가 | INSERT |
| 기존 행 변경 | 식별자로 UPDATE |
| 기존 행 삭제 | 식별자로 DELETE |

`:U`가 SQL을 만들어 주지는 않습니다. 상태와 데이터를 해석하고 SQL을 수행하는 서버 구현이 필요합니다. 삭제 행은 일반 목록과 별도로 관리될 수 있어 rowcount만 검사하면 놓칠 수 있습니다.

## 저장 성공 뒤에도 할 일이 있나요?

서버가 새 사번을 발급하거나 값을 계산했다면 응답에 반영하거나 다시 조회해야 합니다. 클라이언트의 `applyChange()`는 DB 저장 명령이 아니며, 상태 초기화 코드를 임의로 추가하면 안 됩니다.

다른 사용자의 DB 변경도 자동으로 내려오지는 않습니다. 재조회할 때는 아직 저장하지 않은 편집값을 덮어쓸 수 있다는 점을 확인합니다.

저장 실패 시 편집 데이터를 무조건 지우지 않습니다. 응답만 끊겨 성공 여부를 알 수 없다면 재저장 전에 서버 결과를 확인하고, 동시 수정이 가능한 업무는 버전이나 수정 시각으로 충돌을 판별합니다.
